# The Brief

[Read The Brief](https://yogeshkaransharma-code.github.io/the-brief-financial-news/) · [Archive](https://yogeshkaransharma-code.github.io/the-brief-financial-news/archive.html) · [Newsroom status](https://yogeshkaransharma-code.github.io/the-brief-financial-news/status.html)

UK banking, insurance, brokers, intermediaries, pensions, regulation and financial technology. Original, source-attributed articles generated by Gemini and challenged in a separate evidence-review request. No claim of human editorial approval.

## One production pipeline

`.github/workflows/ai-newsroom.yml` is the only collector/writer/publisher/deployer. It runs hourly and near GMT/BST midnight. The former hourly collector is retired. `public-site-health.yml` independently checks the actual production site nightly.

1. Discover leads from regulator/government RSS, industry publications and curated first-party newsrooms. Bounded parallel retrieval; no model requests for discovery.
2. Trace media reports to original documents. Secondary text is never presented to the writer as evidence. Paywalls and access denials are not bypassed.
3. Read the original document completely within extraction limits. Verify the original publication date from publication metadata or an unambiguous dateline. A listing date, RSS updated date or modification date cannot certify freshness.
4. Gemini writes a concise article. A **separate request** sceptically challenges every headline, standfirst, section heading and body sentence, including qualifications and denominators. Source passage IDs resolve to actual captured words. Optional unverified glossary text is omitted.
5. Deterministic controls reject unsupported figures, bad integrity hashes, unreviewed sentences, ambiguous regulatory interpretation, high-risk claims and date mismatches. This is machine review, not independent corroboration of the source itself.
6. The final gate checks that both the original announcement and actual publication occur on the **same UK calendar date**. No weekend catch-up, rolling-24h substitution or stale story backfill.
7. Preserve all approved records, including historical editions, with immutable approval fingerprints. Generate real HTML story pages and archive routes, then deploy GitHub Pages and probe the actual website.

## Gemini and costs

Use only the existing `GEMINI_API_KEY` Actions secret and `gemini-3.5-flash-lite`. Other providers are disabled. No billing settings are changed. No paid search grounding, paid provider fallback, unmetered model switch or repeated AI rewrite is used.

Hard limits: six requests per run, twenty per Pacific quota day (failed requests included), fifteen seconds between requests, at most ten published articles per UK day. A draft needs two calls; failures reduce the attainable count. Five to ten worthwhile articles is an editorial aim when verified same-day news exists, never a forced quota.

Requests are reserved in a durable local ledger before calling Gemini, then committed even if writing fails. Daily quota holds use Google's Pacific reset; short rate limits receive bounded cooldowns. Token usage is reported in logs. The code cannot inspect the Google project's billing tier or guarantee zero cost if its owner enables paid billing outside this repository. Keep the project on its free tier. Limits apply to the Google project, including usage outside The Brief; the local ledger is not Google's authoritative quota meter.

## Meaningful outcomes

`data/status.json` and the public status page record **PUBLISHED**, **NO_QUALIFYING_NEWS**, **DEGRADED** or **BLOCKED**. New articles are counted from the publisher's report, not from a green job or a screened draft. Publication-success job runs only after actual articles and live checks. Missing run reports and discovery failures cannot be labelled proof that no news exists. Blocked or degraded runs create a failing attention job while the site and status remain deployable. GitHub's normal Actions notifications apply; this does not send messages through another service.

## Validation

```
python -m pip install -r scripts/requirements-newsroom.txt
python scripts/run_checks.py
python scripts/build_public.py
python scripts/verify_public.py
python scripts/verify_live.py
```

`verify_browser.py` runs in Actions against production at 390px and 1440px, opens an archived/full article even when today's edition is empty, checks original-source URLs, layout overflow and JavaScript errors, and saves screenshots. A generated local fixture is never counted as live Gemini publication. `AUDIT.md` records the original faults; `OPERATIONS.md` records verification and remaining limitations.

## Data and accountability

- `data/articles.json`: complete canonical approved archive; no 150-record truncation.
- `data/editorial-audits`: version-bound approvals, original date evidence and reviewed claim excerpts for new articles.
- `data/live.json`: discovery cache, excluded from the deployed website (the GitHub repository itself is public).
- `generated-drafts`: source snapshots, held drafts and reports in 90-day Actions artifacts; not deployed as articles.
- `public/data/articles.json`: only today's qualifying reports.
- `public/data/archive.json`, `archive.html`, `edition/YYYY-MM-DD.html`, `story/ID.html`: historical access and complete reading pages.

Legacy articles are preserved as historical reporting with a notice. Their hashes validate provenance, not factual truth or the accuracy of their old source dates. Consequential legal/enforcement stories and incomplete or ambiguous documents remain held. Corrections can be reported through the public repository issue tracker; checked revisions must update the approval hash and show a correction notice.
